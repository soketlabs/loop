# Update docs/design/runtime.md: the maintainer approved the doc with these answers

Replace the "Open questions for the maintainer" list with a "Decisions (maintainer, 2026-11-01)" list, and update the body sections that the answers touch so the doc is consistent:

1. `session_seq` counts only wire updates (UpdateEnvelopes sent to clients), so it is contiguous per Session. Every Event Log record also has `global_seq` (log-wide order). Non-update records (PromptSent, Escalation*, SessionOpened/Closed, ...) have no session_seq of their own (NULL), ordered by global_seq. `latest_seq` = last update's session_seq. Adjust the events table (session_seq nullable; UNIQUE(session_key, session_seq) only where not NULL) and the attach section.
2. Turn semaphore: default 8 concurrent active turns (configurable via `loop serve --max-turns`... name it `--max-active-turns`). Saturation waits (queues), not Busy. A parent blocked inside the `subagent` tool releases its permit while waiting and re-acquires after.
3. Leases: renew every 5 s, stale after 30 s. On startup the Runtime holds runtime.lock (flock), which proves the previous Runtime is dead, so it reclaims leases whose owner is "runtime" immediately. Any other takeover needs stale heartbeat AND dead pid. A live owner is never taken over. Include the worked example: Runtime killed by OOM, then `loop --resume X` takes over after 30 s.
4. Fork becomes one IMMEDIATE transaction in S2.1 (create, copy entries, set parent, all or nothing).
5. Interrupted turn after a crash: existing turn-end update with a new reason value `runtime_restarted`; pinned in schema/golden tests in S2.5-types.
6. `SessionInfo` gains `parent` and `last_active_ms`. `loop attach --new [--cwd DIR]` creates a Session via session/new.
7. Subagent `max_turns` counts model calls in the child. Default: no limit; the parent may set one for bounded jobs. Runaway control: parent cancel cascades, depth limit 2, visible/closeable in `loop attach`. A finished child closes automatically once the parent has its answer (frees the live-Session cap); its log stays.
8. WebSocket listener requires a bearer token even on loopback (match loop-wire socket.rs, not mcp_serve.rs). Stays last; may slip to S3.
