# Policy is layered and each layer can only tighten

Every switchable feature is a Capability (off, ask or on, with an optional scope). Policy is layered Managed Policy → Org → Group → User → Agent Definition → Session, and a lower layer can only make a Capability stricter. An admin can Lock a Capability so nothing below can change it, and a Subagent never gets more than its parent. We chose "most restrictive wins" over a priority-override model because it is the rule a security team can sign off on without reading every layer. It generalises the rule project settings already follow (`docs/permissions.md`). Permission modes (read-only, ask, accept-edits, full-access) become named presets over Capabilities. Deployment Profiles (Personal, Team, Enterprise, Read-only Analyst, Air-gapped) are ready-made Policy bundles.
